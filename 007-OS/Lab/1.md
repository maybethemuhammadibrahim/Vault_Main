*Correction regarding your note on the pipe (`|`) operator:* You noted that `|` is used to execute commands one after the other. This is incorrect. The semicolon (`;`) is used to execute commands sequentially. The pipe (`|`) takes the standard output (stdout) of the command on the left and passes it as standard input (stdin) to the command on the right.

### 1. Core Shell, Operators, and Wildcards

**`man`**

1. **Action:** Displays the manual pages for a given command.
2. **Usage:** `man [command]`
3. **Flags:**
   * `-k` : Search manual page descriptions for a keyword.
   * `-f` : Display a short description of the command (equivalent to `whatis`).
4. **Example:** `man -k "process"` (Finds commands related to processes).
   *Similar Commands:* `info` (reads info documents), `help` (displays shell builtin help).

**`echo`**

1. **Action:** Prints text or variables to the terminal.
2. **Usage:** `echo [string/variable]`
3. **Flags:**
   * `-n` : Displays the output without the trailing newline.
   * `-e` : Enables interpretation of backslash escapes (`\a` plays alert, `\b` removes spaces/backspaces, `\c` produces no further output).
4. **Example:** `echo -e "Hello\bWorld"` (Outputs `HellWorld`).
   *Similar Commands:* `printf` (formats and prints data).

**Shell Operators**

* `|` (Pipe): Passes the output of one command as input to another. Example: `ls -l | grep ".txt"`
* `&&` (AND): Executes the second command *only* if the first command succeeds (returns exit status 0). Example: `mkdir new_dir && cd new_dir`
* `;` (Semicolon): Executes commands sequentially regardless of success. Example: `cd /tmp ; ls`

**Wildcards**
Used for pattern matching in the shell.

* `*` : Matches zero, one, or multiple characters. Example: `ls file*` (Lists `file`, `file1`, `filename`). `ls *2.txt` (Lists anything ending in `2.txt`).
* `?` : Matches exactly one character. Example: `ls file.tx?` (Lists `file.txt`, `file.tx1`, but not `file.tx`).
* `[]` : Matches one specified character out of a set or range. Example: `ls rmt[1-5]` (Lists `rmt1` through `rmt5`).

### 2. System and Process Management

**`date`**

1. **Action:** Prints or sets the system date and time.
2. **Usage:** `date [options] [+format]`
3. **Flags:**
   * `-u` : Print or set Coordinated Universal Time (UTC).
   * `-d` : Display time described by a string, not 'now'.
4. **Example:** `date -d "last Friday"`
   *Similar Commands:* `cal` (displays calendar), `uptime` (shows how long system has been running).

**`shutdown` / `poweroff` / `reboot`**

1. **Action:** Halts, powers down, or restarts the machine.
2. **Usage:** `shutdown [time] [message]`, `reboot`, `poweroff`
3. **Flags (shutdown):**
   * `-r` : Reboot after shutdown.
   * `-c` : Cancel a pending shutdown.
4. **Example:** `shutdown -r +10 "Restarting in 10 minutes"`
   *Similar Commands:* `halt` (instructs hardware to stop all CPU functions).

**`ps`**

1. **Action:** Reports a snapshot of current running processes.
2. **Usage:** `ps [options]`
3. **Flags:**
   * `aux` : Displays all processes running on the system (BSD syntax).
   * `-ef` : Displays all processes with full format listing (System V syntax).
4. **Example:** `ps aux | grep "nginx"`
   *Similar Commands:* `pgrep` (looks up processes based on name).

**`kill`**

1. **Action:** Sends a signal to a process (usually to terminate it).
2. **Usage:** `kill [signal_option] [PID]`
3. **Signals:**
   * `-15` (SIGTERM) : Default. Requests a program to stop, allowing it to save progress and clean up.
   * `-9` (SIGKILL) : Forces the program to stop immediately; unsaved progress is lost.
4. **Example:** `kill -9 63773` (Force kills PID 63773).
   *Similar Commands:* `killall` (kills processes by name), `pkill` (kills processes matching a pattern).

**`df`**

1. **Action:** Reports system disk space usage.
2. **Usage:** `df [options] [file/directory]`
3. **Flags:**
   * `-h` : Human-readable format (e.g., GB, MB).
   * `-m` : Displays file system usage in MBs.
   * `-k` : Displays file system usage in KBs (default).
   * `-T` : Shows the file system type (e.g., ext4, xfs).
4. **Example:** `df -hT`

**`du`**

1. **Action:** Estimates and reports file and directory space usage.
2. **Usage:** `du [options] [file/directory]`
3. **Flags:**
   * `-h` : Human-readable format.
   * `-s` : Display only a grand total for the specified directory.
4. **Example:** `du -sh /var/log/`
   *Similar Commands:* `ncdu` (ncurses disk usage - interactive viewer).

**`top` & `htop`**

1. **Action:** Displays dynamic, real-time views of running processes. `htop` is a visually enhanced, interactive version of `top`.
2. **Usage:** `top` or `htop`
3. **Flags (top):**
   * `-u [user]` : Display processes for a specific user.
   * `-d [seconds]` : Change the delay between screen updates.
4. **Example:** `top -u root`
   *Similar Commands:* `btop`, `glances` (advanced resource monitors).

**`uname`**

1. **Action:** Prints system information.
2. **Usage:** `uname [options]`
3. **Flags:**
   * `-a` : Print all available system information.
   * `-r` : Print the kernel release.
4. **Example:** `uname -r`
   *Similar Commands:* `lscpu` (shows CPU architecture), `lsblk` (lists block devices).

### 3. Network Related Commands

**`ping`**

1. **Action:** Sends ICMP ECHO_REQUEST packets to network hosts to check connectivity.
2. **Usage:** `ping [options] [destination]`
3. **Flags:**
   * `-c [count]` : Stop after sending a specified number of packets.
   * `-i [interval]` : Wait *interval* seconds between sending each packet.
4. **Example:** `ping -c 4 google.com`

**`wget`**

1. **Action:** Non-interactive file downloader from the web.
2. **Usage:** `wget [options] [URL]`
3. **Flags:**
   * `-c` : Resume a partially downloaded file.
   * `-O [file]` : Write documents to a specific file instead of stdout.
4. **Example:** `wget -c http://example.com/largefile.zip`
   *Similar Commands:* `curl` (transfer data from or to a server).

**`hostname`**

1. **Action:** Shows or sets the system's host name.
2. **Usage:** `hostname [name]`
3. **Flags:**
   * `-I` : Display all network addresses of the host.
4. **Example:** `hostname -I`

**`ip`**

1. **Action:** Shows and manipulates routing, network devices, interfaces, and tunnels.
2. **Usage:** `ip [OPTIONS] OBJECT {COMMAND | help}`
3. **Common Objects/Commands:**
   * `a` or `addr` : Show IP addresses.
   * `r` or `route` : Show routing table.
4. **Example:** `ip a` (Shows all IP addresses).
   *Similar Commands:* `ifconfig` (deprecated, but still used on older systems).

### 5. Search and Permissions (Detailed Usage)

**`locate`**

* **Action:** Finds files by name using a pre-built database. Extremely fast but may not show recently created files until the database updates.
* **Detailed Usage:** The database is usually updated daily via a cron job running `updatedb`.
* **Common Flags:**
  * `-i` : Ignore case distinctions.
  * `-c` : Print only the count of matching entries.
* **Example:** `locate -i "*.jpg"` (Finds all JPEG files quickly, regardless of capitalization).

**`find`**

* **Action:** Searches for files in a directory hierarchy based on varying criteria (name, size, type, time, permissions). It is slower than `locate` but does real-time disk reads and is highly accurate.
* **Detailed Usage:** `find [path] [expression]`
* **Common Expressions:**
  * `-name [pattern]` : Base of file name matches pattern.
  * `-type [f/d/l]` : File is of type f (regular file), d (directory), l (symlink).
  * `-size [+|-][size]` : Find files larger (+) or smaller (-) than size (e.g., `+50M`).
  * `-mtime [days]` : Data was last modified *n* days ago.
  * `-exec [command] {} \;` : Execute a command on the results.
* **Example:** `find /var/log -type f -name "*.log" -size +100M -exec rm -i {} \;` (Finds log files over 100MB in `/var/log` and prompts to delete them).

**`grep`**

* **Action:** Prints lines matching a specified text pattern or regular expression within files.
* **Detailed Usage:** `grep [options] "pattern" [file]`
* **Common Flags:**
  * `-i` : Ignore case.
  * `-v` : Invert match (show lines that *do not* match).
  * `-r` / `-R` : Read all files under each directory recursively.
  * `-n` : Prefix each line of output with the line number.
* **Example:** `grep -rin "error" /var/log/nginx/` (Recursively searches for "error", ignoring case, in the Nginx log directory and prints line numbers).

**`chmod`**

* **Action:** Changes file mode bits (read/write/execute permissions).
* **Detailed Usage:** Can be used with symbolic mode (u, g, o, a combined with +, -, =) or numeric (octal) mode.
  * **Numeric:** 4 = Read, 2 = Write, 1 = Execute.
    * `7` = 4+2+1 (Read, Write, Execute)
    * `6` = 4+2 (Read, Write)
    * `5` = 4+1 (Read, Execute)
  * **Symbolic:** `u` (user/owner), `g` (group), `o` (others), `a` (all).
* **Common Flags:**
  * `-R` : Change files and directories recursively.
* **Examples:**
  * Numeric: `chmod 755 script.sh` (Owner can rwx; group and others can rx).
  * Symbolic: `chmod u+x script.sh` (Adds execute permission for the owner).

**`chown`**

* **Action:** Changes file owner and group.
* **Detailed Usage:** `chown [owner][:[group]] file`
* **Common Flags:**
  * `-R` : Operate on files and directories recursively.
* **Examples:**
  * `chown alice:developers project_dir/` (Changes owner to 'alice' and group to 'developers').
  * `chown root script.sh` (Changes owner to root; group remains unchanged).
