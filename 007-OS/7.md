### 1. The Bounded-Buffer Problem (Producer-Consumer)

**The Actual Problem:**
You have a producer creating items and a consumer using them. They share a fixed-size storage area (buffer). 
* The producer must not try to add data if the buffer is full.
* The consumer must not try to remove data if the buffer is empty.
* They must not modify the buffer at the exact same time to prevent data corruption (race condition).

**Significance of Variables:**
* `int n`: The maximum capacity of the buffer.
* `semaphore mutex = 1`: Acts as a binary lock to ensure mutual exclusion. Only one process (producer or consumer) can access the buffer array at any exact moment.
* `semaphore full = 0`: A counting semaphore tracking how many slots currently contain items. Initialized to 0 because the buffer starts empty.
* `semaphore empty = n`: A counting semaphore tracking how many slots are empty. Initialized to `n` because all slots are initially available.

**Pseudocode:**

*Producer Structure:*
```c
while (true) {
    /* produce an item in next_produced */
    
    wait(empty); // Decrement empty slots (blocks if 0)
    wait(mutex); // Lock the buffer
    
    /* add next_produced to the buffer */
    
    signal(mutex); // Unlock the buffer
    signal(full);  // Increment full slots
}
```

*Consumer Structure:*
```c
while (true) {
    wait(full);  // Decrement full slots (blocks if 0)
    wait(mutex); // Lock the buffer
    
    /* remove an item from buffer to next_consumed */
    
    signal(mutex); // Unlock the buffer
    signal(empty); // Increment empty slots
    
    /* consume the item in next_consumed */
}
```

**C Implementation (Pthreads):**
```c
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>

#define BUFFER_SIZE 10

int buffer[BUFFER_SIZE];
int in = 0, out = 0;
sem_t mutex, empty, full;

void* producer(void* arg) {
    int item = 0;
    while (1) {
        sem_wait(&empty);
        sem_wait(&mutex);
        
        buffer[in] = item++;
        in = (in + 1) % BUFFER_SIZE;
        
        sem_post(&mutex);
        sem_post(&full);
        
        printf("Produced: %d\n", item - 1);
    }
    return NULL;
}

void* consumer(void* arg) {
    while (1) {
        sem_wait(&full);
        sem_wait(&mutex);
        
        int item = buffer[out];
        out = (out + 1) % BUFFER_SIZE;
        
        sem_post(&mutex);
        sem_post(&empty);
        
        printf("Consumed: %d\n", item);
    }
    return NULL;
}

int main() {
    pthread_t prod, cons;
    sem_init(&mutex, 0, 1);
    sem_init(&empty, 0, BUFFER_SIZE);
    sem_init(&full, 0, 0);
    
    pthread_create(&prod, NULL, producer, NULL);
    pthread_create(&cons, NULL, consumer, NULL);
    
    pthread_join(prod, NULL);
    pthread_join(cons, NULL);
    
    sem_destroy(&mutex);
    sem_destroy(&empty);
    sem_destroy(&full);
    return 0;
}
```

### 2. The Readers-Writers Problem

**The Actual Problem:**
A shared database is accessed by two types of processes: readers and writers. 
* Reading does not change data, so multiple readers can read at the same time safely.
* Writing changes data. If a writer is writing, no one else (neither reader nor writer) can access the database.
The challenge is managing access efficiently without causing a process to wait forever (starvation).

**Significance of Variables:**
* `semaphore rw_mutex = 1`: The main lock for the database. Writers must acquire this to write. The *first* reader acquires it to lock out writers, and the *last* reader releases it.
* `semaphore mutex = 1`: A separate lock used exclusively to protect the `read_count` variable from race conditions when multiple readers enter or exit.
* `int read_count = 0`: Tracks exactly how many readers are currently accessing the database.

**Pseudocode:**

*Writer Structure:*
```c
while (true) {
    wait(rw_mutex); // Request exclusive access
    
    /* writing is performed */
    
    signal(rw_mutex); // Release exclusive access
}
```

*Reader Structure:*
```c
while (true) {
    wait(mutex); // Lock read_count variable
    read_count++;
    if (read_count == 1) // If first reader, lock out writers
        wait(rw_mutex);
    signal(mutex); // Unlock read_count variable
    
    /* reading is performed */
    
    wait(mutex); // Lock read_count variable
    read_count--;
    if (read_count == 0) // If last reader, let writers in
        signal(rw_mutex);
    signal(mutex); // Unlock read_count variable
}
```

**C Implementation (Pthreads):**
```c
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>

sem_t rw_mutex, mutex;
int read_count = 0;

void* reader(void* arg) {
    while (1) {
        sem_wait(&mutex);
        read_count++;
        if (read_count == 1)
            sem_wait(&rw_mutex);
        sem_post(&mutex);

        printf("Reader %ld is reading\n", (long)arg);

        sem_wait(&mutex);
        read_count--;
        if (read_count == 0)
            sem_post(&rw_mutex);
        sem_post(&mutex);
    }
    return NULL;
}

void* writer(void* arg) {
    while (1) {
        sem_wait(&rw_mutex);
        printf("Writer is writing\n");
        sem_post(&rw_mutex);
    }
    return NULL;
}

int main() {
    pthread_t w, r1, r2;
    sem_init(&rw_mutex, 0, 1);
    sem_init(&mutex, 0, 1);

    pthread_create(&w, NULL, writer, NULL);
    pthread_create(&r1, NULL, reader, (void*)1);
    pthread_create(&r2, NULL, reader, (void*)2);

    pthread_join(w, NULL);
    pthread_join(r1, NULL);
    pthread_join(r2, NULL);

    sem_destroy(&rw_mutex);
    sem_destroy(&mutex);

    return 0;
}
```

**Variations & Flaws:**
1.  **First Variation (Reader Preference):** As implemented above. If readers keep arriving, the `read_count` never hits 0. Writers wait indefinitely (Writer Starvation).
2.  **Second Variation (Writer Preference):** If a writer wants to write, no new readers are allowed to start. Readers may wait indefinitely (Reader Starvation).

### 3. The Dining-Philosophers Problem

**The Actual Problem:**
Five philosophers sit around a table with a bowl of rice. There are five chopsticks total, placed between them. A philosopher needs two chopsticks (left and right) to eat. They must acquire shared resources (chopsticks) in a way that prevents them from getting stuck waiting for each other permanently.

**Pseudocode (Naive Semaphore Solution):**
*Shared Data:* `semaphore chopstick[5]` (all initialized to 1).

*Philosopher i:*
```c
while (true) {
    wait(chopstick[i]);           // Pick up left chopstick
    wait(chopstick[(i + 1) % 5]); // Pick up right chopstick
    
    /* eat for awhile */
    
    signal(chopstick[i]);           // Release left
    signal(chopstick[(i + 1) % 5]); // Release right
    
    /* think for awhile */
}
```

**Problems with this Algorithm:**

1.  **Deadlock:** * Occurs if all five philosophers get hungry at the exact same time and pick up their left chopstick (`wait(chopstick[i])`).
    * All chopstick semaphores drop to 0.
    * When they try to pick up the right chopstick, they all block indefinitely. It becomes a circular dependency where everyone has one chopstick and is waiting for the person next to them to drop theirs. The system permanently halts.
2.  **Starvation:**
    * Occurs if the timing is unbalanced. For example, fast philosophers put down and pick up chopsticks quickly, repeatedly getting two chopsticks. Slow philosophers might always find at least one chopstick taken by a fast neighbor, meaning they never get to eat.

**Solutions to Prevent Deadlock:**
1.  **Atomic Acquisition:** Force philosophers to pick up both chopsticks at the exact same time. If both are not available, they pick up neither.
2.  **Resource Limitation:** Allow a maximum of four philosophers to sit at the table with five chopsticks. By Pigeonhole Principle, at least one philosopher is guaranteed to have access to two chopsticks, breaking the circular wait.
