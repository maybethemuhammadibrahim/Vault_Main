# COAL Lecture Notes: Program Execution & Processor Modes

## 1. The Assembly Toolchain (Assemble-Link-Execute Cycle)

To convert human-readable assembly code into a running program, the system performs a sequence of translations known as the Assemble-Link-Execute cycle.

### A. The Assembler (MASM)

* **Definition:** A utility program that translates source code files (`.asm`) containing assembly mnemonics into an **object file** (`.obj`).
* **Function:** It converts mnemonics (e.g., `MOV`, `ADD`) into machine language (opcodes).
* **Output:** The object file contains raw machine code but is not yet executable because memory addresses for external procedures (libraries) have not been resolved.
* **Listing File (`.lst`):** An optional text file generated during assembly. It is a critical tool for debugging and verification. It contains:
1. **Numeric Address:** The offset of each instruction relative to the segment start.
2. **Machine Code:** The hex bytes generated for each instruction.
3. **Source Code:** The original code written by the programmer.
4. **Symbol Table:** A dictionary of all program identifiers (variables, labels) and their segments/offsets.



### B. The Linker (`LINK.EXE`)

* **Definition:** A utility that combines the user's object file with system libraries to create an **executable file** (`.exe`).
* **Function:**
* Resolves "External References" (calls to procedures inside library files like `Irvine32.lib` or `kernel32.lib`).
* Combines code from multiple object modules into a single program.



### C. The OS Loader

* **Definition:** A component of the Operating System responsible for loading the executable from disk into physical memory.
* **Workflow:**
1. **Search:** OS looks for the filename in the current directory, then in the system `PATH`.
2. **Allocation:** OS reads the file size, allocates a memory block, and assigns the program a **Process ID (PID)**.
3. **Address Resolution:** If the program contains absolute addresses, the loader may adjust (relocate) them based on where the program was loaded in memory.
4. **Execution:** The OS points the CPU’s Instruction Pointer (IP/EIP) to the program's entry point, transferring control to the program.

## 2. Memory Segmentation and Descriptor Tables

### A. Memory Segments

A segment is a logical block of consecutive memory. In x86 architecture, programs are divided into three primary segments to organize execution:

1. **Code Segment (CS):** Contains the executable machine instructions.
2. **Data Segment (DS):** Contains global variables and static data.
3. **Stack Segment (SS):** Contains the runtime stack, used for local variables, function parameters, and return addresses.
*(Note: An "Extra Segment" (ES, FS, GS) is often used for string operations or specialized OS data structures.)*

### B. The Descriptor Table (Protected Mode Concept)

The user notes mention an "OS table" that tracks program location. In x86 Protected Mode, this is formalized as the **Descriptor Table**.

* **Definition:** A data structure (lookup table) maintained by the OS that holds descriptions of the memory segments.
* **Function:** Instead of the Segment Register holding the actual physical address (as it does in Real Mode), it holds a **Selector** (an index).
* **How it works:**
1. The CPU reads the Selector from the Segment Register (e.g., `DS`).
2. It uses this index to look up a **Segment Descriptor** in the Global Descriptor Table (GDT).
3. The Descriptor contains the **Base Address** (where memory starts), the **Segment Limit** (size), and **Access Rights** (Read/Write/Execute permissions).


* **Why it matters:** This allows the OS to move memory physically without breaking the program (Virtual Memory) and prevents programs from overwriting each other (Memory Protection).

## 3. The EFLAGS Register

The EFLAGS (Extended Flags) register is a 32-bit register containing individual bits that report CPU status or control CPU operations.

### A. Status Flags

These are updated automatically by the CPU after arithmetic or logical operations (e.g., `ADD`, `SUB`, `CMP`, `AND`). *Note: Simple data movement instructions like `MOV` generally do **not** affect these flags.*

| Flag | Name | Function & Edge Cases |
| --- | --- | --- |
| **CF** | **Carry Flag** | **Unsigned Arithmetic.** Set when a result is too large for the destination (overflows the MSB) or a borrow occurs.<br>

<br>*Edge Case:* `AL = FFh`. `ADD AL, 1`. Result is `00h`. The unsigned value 255 + 1 = 256 (too big for 8 bits). **CF=1**. 

| --- | --- | --- |
| **OF** | **Overflow Flag** | **Signed Arithmetic.** Set when the result is valid mathematically but incorrect for the binary storage size (e.g., Positive + Positive = Negative).<br>

<br>*Edge Case:* `AL = 7Fh` (+127). `ADD AL, 1`. Result `80h` (-128 in signed byte). **OF=1** (Signed overflow), but **CF=0** (No unsigned carry). |

| --- | --- | --- |
| **ZF** | **Zero Flag** | Set (1) when the result of an operation is Zero. Clear (0) if non-zero.<br>

<br>*Usage:* Crucial for `CMP` instructions. If `CMP A, B` results in ZF=1, then A equals B. |

| --- | --- | --- |
| **SF** | **Sign Flag** | Set equal to the Most Significant Bit (MSB) of the result. 1 = Negative, 0 = Positive.<br>

<br>*Note:* Useful mostly for signed arithmetic. |

| --- | --- | --- |
| **PF** | **Parity Flag** | Set if the **least significant byte (lowest 8 bits)** of the result contains an even number of 1s.<br>

<br>*Edge Case:* If `AX = 0100h`. The 1 is in the high byte. The low byte is `00` (zero 1s is even). **PF=1**. Many students mistakenly check the whole register. |

| --- | --- | --- |
| **AF** | **Auxiliary Carry** | Set when there is a carry out of bit 3 into bit 4. Used exclusively for **BCD (Binary Coded Decimal)** arithmetic adjustments. |

### B. Control Flags

These flags are deliberately set or cleared by the programmer to modify CPU behavior.

| Flag | Name | Function & Instruction Control |
| --- | --- | --- |
| **DF** | **Direction Flag** | Controls the memory traversal direction for string instructions (`MOVS`, `CMPS`).<br>

<br>**DF=0 (Clear):** Processing moves forward (Low address  High). Set by `CLD`.<br>

<br>**DF=1 (Set):** Processing moves backward (High address  Low). Set by `STD`. |
| **IF** | **Interrupt Flag** | **IF=1:** CPU responds to hardware interrupts (keyboard, mouse).<br>

<br>**IF=0:** CPU ignores (masks) hardware interrupts.<br>

<br>*Note:* Critical sections of OS code clear IF to prevent interruption during delicate tasks. |
| **TF** | **Trap Flag** | **Debugging.** If TF=1, the CPU halts after **every single instruction**, triggering an interrupt. This allows debuggers to implement "Single Step" functionality. |

## 4. x86 Modes of Operation

### A. Real-Address Mode (16-bit)

The native state of the original Intel 8086.

* **Memory Space:** Limited to 1 MB ( bytes). range: `00000h` to `FFFFFh`.
* **Addressing:** Uses **Segmented Addressing**.
* **Formula:** 
* *Note:* Multiplying by 16 is equivalent to shifting the hex digit one place to the left.


* **Danger:** No memory protection. A program can write to OS memory, causing a crash.
* **Example Calculation:**
* Given Segment: `A1F0h`
* Given Offset: `04C0h`
* Shift Segment: `A1F00h` (Multiply by 10h)
* Add Offset: `+ 04C0h`
* **Linear Address:** `A23C0h`



### B. Protected Mode (32-bit / 64-bit)

The native mode of modern OSs (Windows, Linux).

* **Memory Space:** 4 GB (32-bit) to 64 GB+ (with PAE).
* **Protection:** Hardware enforces boundaries. A program cannot access memory segments belonging to another program or the OS.
* **Virtual Memory:** Supports Paging, allowing the OS to swap memory to the hard disk.

### C. Virtual-8086 Mode

* **Definition:** A "sandbox" sub-mode within Protected Mode.
* **Purpose:** Allows legacy 16-bit Real Mode applications (like MS-DOS games) to run safely inside a modern 32-bit OS.
* **Safety:** If the DOS program crashes, it only crashes its virtual machine, not the entire OS.

### D. System Management Mode (SMM)

* **Definition:** A specialized diagnostic mode used by the motherboard firmware (BIOS/UEFI).
* **Purpose:** Power management (sleep/wake), hardware control, and thermal protection. It is transparent to the standard Operating System.

### EFLAGS "Gotchas"

* **CF vs OF:** CF is for **Unsigned** errors. OF is for **Signed** errors.
* **PF:** Only checks the **Lower 8 bits**, not the full register.
* **ZF:** `ZF=1` means the result was **Zero** (e.g., `5 - 5`).
* **DF:** `CLD`  Forward (Up); `STD`  Backward (Down).
