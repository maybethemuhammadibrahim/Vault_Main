
# COAL Lecture Notes: Systems, Assembly, and Architecture

## 1. Computer Architecture vs. Computer Organization

While often used interchangeably, these terms refer to distinct aspects of computer design.

* **Computer Architecture (The "What"):**
* Refers to the attributes of a system visible to the **programmer** (specifically the assembly language programmer).
* It defines the logical interface of the hardware.
* **Includes:** Instruction set architecture (ISA), data representation (bits/bytes), addressing modes, and I/O mechanisms.
* *Example:* Deciding whether a processor supports a specific multiplication instruction is an architectural decision.


* **Computer Organization (The "How"):**
* Refers to the operational units and their interconnections that realize the architectural specifications.
* It concerns the physical implementation and hardware details transparent to the programmer.
* **Includes:** Control signals, memory technology, bus interfaces, and clock frequencies.
* *Example:* How the multiplier is implemented in hardware (e.g., using a specific logic gate arrangement) is an organizational decision.



| Feature | Computer Architecture | Computer Organization |
| --- | --- | --- |
| **Focus** | Logic & Behavior (User View) | Physical Structure (Hardware View) |
| **Concern** | *What* the system does. | *How* the system implements it. |
| **Change** | Rarely changes within a family. | Changes frequently (e.g., Intel i7 vs i9). |

## 2. Programming Language Hierarchy

### High-Level Languages (HLL)

Languages such as C++, Java, and Python designed to abstract hardware details.

* **Abstraction Level:** High. They are closer to human language and further from machine language.
* **Relationship:** **One-to-Many**. A single HLL statement (e.g., `cout << A`) expands into multiple assembly or machine instructions.
* **Portability:** Machine Independent. Source code can run on different processors with little modification.
* **Development:** Faster development and easier maintenance due to readability and abstraction.

### Assembly Language (ASM)

A low-level programming language that provides a symbolic representation of machine code.

* **Abstraction Level:** Low. Designed for a specific processor family (e.g., x86, ARM).
* **Relationship:** **One-to-One**. Each ASM instruction (mnemonic) corresponds directly to a single machine language instruction.
* **Key Components:** Uses mnemonics (short codes like `MOV`, `ADD`, `SUB`, `CALL`) instead of raw binary.
* **Role:** Acts as a transparent interface to hardware.
* **Why use it?**
1. **Direct Hardware Control:** Essential for writing device drivers and embedded systems.
2. **Optimization:** Allows manual optimization for speed and memory efficiency where compilers fail.
3. **Understanding:** clarifies how software interfaces with the CPU, memory, and OS.



### Machine Language

The native language of the CPU, consisting entirely of binary (0s and 1s). It is the only language the processor directly understands.

## 3. Basic Microcomputer Design

The fundamental components of a computer system based on the Von Neumann model.

### A. The Central Processing Unit (CPU)

The "brain" of the computer responsible for calculations and logic.

* **Control Unit (CU):** Decodes instructions and directs the flow of data.
* **Arithmetic Logic Unit (ALU):** Performs arithmetic (, , ,  ) and logical (AND, OR, NOT) operations.
* **Registers:** High-speed storage locations directly inside the CPU used for holding intermediate data and addresses.
* **Clock:** Synchronizes internal operations.

### B. Memory Storage Unit

Holds instructions and data while the program is running.

* **RAM (Random Access Memory):** The primary workspace. Data must be copied from RAM to the CPU to be processed.

### C. System Buses

A bus is a collection of parallel wires used to transfer data between components. The generic system bus typically consists of four distinct bus types:

1. **Data Bus:**
* **Function:** Transfers instructions and data between the CPU and memory/IO.
* **Direction:** **Bidirectional** (Data moves both ways).


2. **Address Bus:**
* **Function:** Holds the physical memory addresses of data or instructions the CPU wants to access.
* **Direction:** **Unidirectional** (CPU  Memory).


3. **Control Bus:**
* **Function:** Carries binary signals to synchronize actions (e.g., Read, Write, Interrupt).
* **Direction:** Mixed (signals go both ways depending on the line).


4. **I/O Bus:**
* **Function:** Specifically transfers data between the CPU and peripheral devices (Input/Output).

## 4. Instruction Execution Cycle

The CPU executes a "Fetch-Decode-Execute" cycle for every machine instruction.

**The Role of the Instruction Pointer (IP/EIP):**
The IP register always contains the address of the *next* instruction to be executed.

**The Cycle Steps (Irvine Model):**

1. **Fetch:** The CPU reads the instruction from the memory address stored in the Instruction Pointer (IP) and places it in the instruction queue.
2. **Increment:** The IP is incremented to point to the next instruction.
3. **Decode:** The CPU analyzes the binary bit pattern to determine the operation and if operands (input values) are required.
4. **Fetch Operands:** If the instruction uses inputs from memory, the CPU calculates their addresses and reads them into registers.
5. **Execute:** The CPU performs the operation using the ALU. Flags (Zero, Carry, Overflow) are updated based on the result.
6. **Store Output:** If the instruction produces a result, it is written back to the destination operand (register or memory).

## 5. Memory Access and Timing

### Clock Cycles

* **Definition:** The basic unit of time for CPU machine instructions, generated by a system clock.
* **Execution Time:** Most instructions require at least one clock cycle. Complex instructions (like multiplication on older 8088 processors) may require 50+.
* **Wait States:** Empty clock cycles where the CPU pauses because the memory or I/O device is too slow to respond immediately.

### Reading from Memory (The Read Cycle)

Memory access is significantly slower than register access. A standard memory read involves four logical steps, each typically taking one clock cycle:

1. **Address:** CPU places the memory address of the value on the **Address Bus**.
2. **Control:** CPU asserts the **RD** (Read) pin/signal on the Control Bus.
3. **Wait:** CPU waits for memory chips to respond (Memory Access Time).
4. **Transfer:** Data is copied from the **Data Bus** into the CPU's destination operand.
---
1. Place the address of the value you want to read on the address bus.
2. Assert (change the value of) the processor’s RD (read) pin.
3. Wait one clock cycle for the memory chips to respond.
4. Copy the data from the data bus into the destination operand.

## 6. Cache Memory

**Problem:** The speed mismatch between the fast CPU and slow RAM (Von Neumann Bottleneck).
**Solution:** Cache is high-speed static RAM (SRAM) located closer to the CPU to hold frequently accessed data.

### Principles of Caching

* **Temporal Locality:** If data is accessed once, it is likely to be accessed again soon (e.g., instructions inside a loop).
* **Spatial Locality:** If data is accessed, nearby data is likely to be accessed soon (e.g., arrays or sequential instruction execution).

### Cache Operation

* **Cache Hit:** The CPU finds the required data in the Cache (Fast).
* **Cache Miss:** The data is not in Cache; the CPU must retrieve it from main RAM (Slow).

### x86 Cache Hierarchy

1. **Level-1 (L1) Cache:** Primary cache located directly on the CPU die. Fastest but smallest.
2. **Level-2 (L2) Cache:** Secondary cache. Slightly slower than L1 but larger. Connected via a high-speed bus.

# ⚡ Exam Cheat Sheet: Quick Revision

### Key Definitions

* **ISA (Architecture):** The programmer-visible interface (Instruction Set).
* **Microarchitecture (Organization):** The hardware implementation.
* **Mnemonic:** A symbolic name for an opcode (e.g., `MOV`).
* **Bus:** Parallel wires for data transfer.
* **Wait State:** A clock cycle wasted waiting for slow hardware.

### HLL vs. Assembly

|  | HLL | Assembly |
| --- | --- | --- |
| **Relation** | 1-to-Many | 1-to-1 |
| **Portability** | Machine Independent | Machine Specific |
| **Use Case** | Apps, Logic | Drivers, Embedded, Speed |

### The Execution Cycle (Simplified)

1. **Fetch** instruction (at IP).
2. **Increment** IP.
3. **Decode** bits.
4. **Fetch Operands** (if needed).
5. **Execute** op.
6. **Store** result.

### Memory Read Steps

1. **Address** on Address Bus.
2. **Read Signal** asserted.
3. **Wait** for response.
4. **Data** moves to CPU via Data Bus.
